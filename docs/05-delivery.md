# 交付计划与验收标准

版本：v0.3，2026-09-21。当前执行M2整个工作包，历史M0/M1保留。产品范围见01，规则见02，体验见03，技术见04。本文不以历史PASS预填本轮结论，实际退出码和证据只在STATUS维护。

## 1. 范围与阶段原则

本项目从新仓库开始，不执行旧项目的任何工作包。先完成有最终制作水准的可玩片段，再扩充内容；不是先搭课程平台，也不是让灰盒和类图替代游戏。

负责人明确希望切断旧页面牵引。负责人2026-09-21明确授权完成整个M2，替代扩展前等待M1确认的限制；本轮运行画面仍需最终确认，确认不是教学审核或儿童趣味证明。M1 若仍像表单网页，继续修正同一场景，不靠新关卡数量掩盖。

## 2. 里程碑

### M0 · 新工程与制作基线

在本仓库独立分支初始化工程，核对当前文档和本地状态。创建真实依赖/锁文件、游戏实例、单视口餐车与原始资源登记。先取得可用的狸花猫参考，制作当前镜头需要的资产；不要从旧截图抠图。

通过最小浏览器冒烟确认渲染、触控输入、声音激活、资源加载和构建入口。不得只凭模板可运行就报告游戏已有可玩性。M0 是工程准备，不是可交卷成品。

### M1 · 完整制作、低龄化玩法与移动端体验升级

本轮明确加入三个轻量入口：跟着小猫做（单客单盘）、帮客人准备食物（单客有限变化）、小小餐车营业中（双客双盘可选便签）。三模式与各自教学均属 M1，不因旧阶段范围排除。正式首页进入可操作餐车，完成“苹果汁 + 苹果香蕉”的代表性双订单。包含意义演示、果汁机真实加工、两托盘占用、小猫一条真实取料便签、错误交付修正、取消/放回、短交付反馈、暂停及刷新恢复。

至少实际走通串行和交错两条准备路径，证明设备等待期间玩家可以做别的事。两条路径不靠预置通关状态或测试后门。角色、物品、机器、声音在运行页面形成完整表现，手机不需要滚动寻找操作。

交付手机竖屏和平板的实际浏览器截图/录像、操作路径、失败修复与负责人待确认项。负责人确认记录需有真实反馈；没有反馈写 AWAITING_OWNER_REVIEW，不由 agent 自评替代。

### M2 · 故事驱动餐车、低门槛操作与英语学习闭环

本包包括小院首页四入口、长辈交接序章、果汁/冰淇淋/三明治/汉堡四章与社区小食会；点击优先、角色连续动作；无尽补单、完整配对与WordSpell；内容驱动英语与独立证据、保存与制作音频。全部属于本包，不缩成入口或单配方。

一个负责人按以下可复核阶段提交，使用既有权威文档，不建平行蓝图：

- [x] A 动作/输入：`src/game/input.ts`、独立 `src/game/actor.ts` 和规则任务合同；先补教学退出/接续/重复事件/双击回归，执行 `npm test` 定向测试与实际Canvas操作。
- [x] B 制作/内容：`src/content/recipes.ts`、`chapters.ts`、`learning.ts`，`src/rules` 设备/组合/订单/快照。按真实命令验证四食谱输入输出、重复命令、满台和读档。
- [x] C 贯通：`src/app/Home.tsx`、`Story.tsx`、`Lesson.tsx`、`Settings.tsx` 与营业场景拆分，序章→四章→结局、继续/重玩/解锁，沿正常首页录制。
- [x] D 回访：有界无尽生成与保存，`src/rules/minigames.ts` / `src/app/MiniGames.tsx` 有限题组、反馈、结算/重玩/返回；独立目标不泄露。
- [x] E 制作与整体修整：独立背景/长辈/食材/设备/动作资源接入，实际hash/Alpha清单，开发语音及过程声；手机/Pad连续录像、加载量与操作段采样。
- [x] F 交付：现有typecheck/lint/build/resources/test/test:browser真实退出码；更新STATUS和AI记录；阶段提交推送PR，不合并。核对既有站点版本，未部署写PENDING_DEPLOYMENT。

已勾选项表示本轮实现/本地证据/PR交付，T12负责人运行确认以及教研、听审、实机、儿童观察仍独立待验，具体结果见STATUS。

### M3 · 可靠性与体验修整

完善满盘/双 READY/助手预留恢复、重开/损坏存档/后台、语音失败、触控取消与横竖屏。检查实际资源清单、句子接受范围、对比度与文字可读性。记录同设备/同路径性能，修复真实卡顿，不能预报 FPS 提升。

桌面浏览器、移动模拟、实体设备和儿童观察分别填写。目标儿童不可获取时可做成人可用性检查，但不要把成人反馈改名为儿童验证。

### M4 · 参赛交付

依据用户提供的活动信息，目标提交时间为 2026-09-23 18:00；该日期是项目背景，不允许以期限为由虚构通过。交付可访问的 HTTPS 试玩网址、简短设计说明、操作说明、真实 AI 使用记录和必要限制。

部署需核对实际授权、托管位置与访问权限。私有源码不妨碍单独安排试玩权限，但不能自动把仓库改公开。链接本身要在未登录条件下核验；GitHub PR、设计图或本地 localhost 不是对外试玩。

## 4. 设备、性能与试玩

工程基准视口为 360×640、390×844、768×1024、1024×768 与桌面；至少从手机布局完成一局，平板验证本轮双客双盘与四类食谱设备均可操作。真实设备目标为 iPhone Safari、Android Chrome、iPad Safari，分别记录机型、系统、浏览器、方向与网络。模拟 WebKit 不是实体 iPhone。

记录输入反馈、并行设备、连续交付和重开后的表现，实际采样再比较目标预算。不要用只播放待机画面的 FPS 证明高峰操作性能。网络缓存命中与首次加载要分开。

儿童观察在监护人同意和适当环境下开展，不要求上传姓名、头像或录音。观察四件事：能否自己找到操作；是否主动利用等待；误操作后是否知道怎样修正；是否愿意再试一个组合。成人指出答案的步骤标为支持。无样本量与研究设计不推断教学提升。

## 5. 完成状态分开判断

| 维度 | 改为通过的条件 |
| --- | --- |
| ENGINEERING_READY | 首包实装、必要规则/构建/HTTP 检查通过，已知严重故障解决 |
| VISUAL_ACCEPTED | 负责人针对真实运行画面/动作明确确认，不是仅看效果图 |
| DEVICE_VALIDATED | 实体目标设备有真实记录；模拟视口只能提供工程布局证据 |
| CONTENT_REVIEWED | 词句、图像指代、正式语音和接受表达由真实教研/听审确认 |
| FUN_OBSERVED | 有具体试玩行为和限制说明；不代表所有孩子喜欢 |
| PUBLIC_RELEASE_READY | 工程、资源权利、内容/设备条件、访问权限与实际部署验收满足 |

最初文档阶段所有维度均 NOT_RUN/PENDING，当前执行结果见 STATUS。工程可玩不自动使其他维度通过。缺外部条件时写 BLOCKED/PENDING，继续不依赖该条件的制作与验证。

## 6. 提交材料与 AI 使用记录

设计说明控制在能快速阅读的范围：主题、谁在玩、核心操作、英语怎样有用、AI 实际用于什么、可玩网址和限制。不得把计划中的助手说成实时智能 NPC，不声称已被公司产品采纳。

AI 日志只记真实行为：日期、工具、任务、产物路径、人工修改、来源/审核状态。最初文档交付属于 AI 辅助设计。后续实际代码、新图片与开发语音制作记录见 AI-usage.md；没有已听审正式录音的证据。

素材权利、录音听审、教研与隐私检查不是许可证文件自动授予的状态。未审核资源可在开发版清楚展示限制，不能更改审核标记来取得公开发布资格。

## 7. Git 与交付报告

一个实现负责人负责一个里程碑，另一个工具可审查或负责不重叠资产任务。默认独立分支与阶段提交，推送后建立 PR，不自动合并、强推或改权限。旧仓库不动。

每次报告：baseline/final full SHA、分支/PR、实际入口变化、对应文档差异、执行命令/退出码/环境、浏览器证据、未运行/失败/外部限制。证据对应当前实现，不沿用历史 PASS。

文档只做相对引用、状态与范围一致性检查；游戏测试在实际实现后运行。运行命令必须以已存在的 package.json 为准，不能拿规划中的命令声称执行过。
