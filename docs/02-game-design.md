# 规则 · 活动、厨房与分享

## 三种任务的唯一判定边界

| 类型 | 判定 | 物品与记录 |
| --- | --- | --- |
| 明确订单 | REQUESTS 产品与数量多重集合严格相等，排列无关；缺、错、额外均不成功 | 明确交付才记录听请求尝试；错单保留全盘，不能自动转给别的客人 |
| 开放委托 | 活动配置声明有效集合/份数/类别；UI显示可选方案，规则核再次校验 | 使用同一托盘/物品实例与动作时钟，接收才进活动；记操作与选择，不能当独立听力 |
| 自由制作 | 任意合法配方与可食用成品、最多三份，无订单标准答案 | 真实输入消耗/输出；作品保存为记忆快照，食品仍只在一处；不发订单成绩 |

配方来自 src/content/recipes.ts；订单来自 catalog；本包活动内容来自 content/adventure.ts，判定与进度由 rules/adventure.ts。Phaser/DOM只投影，不复制规则。

## 活动因果

第三章开场兔兔明确要芝士三明治，刺刺明确要蔬菜三明治，两单从接单起固定。首份在角色接收阶段完成的交付决定路径：

- 兔兔先：可检查篮子，看到还需要一份三明治和一份水果；实际制作并整盘送入篮子（两种三明治与苹果/香蕉均有效），随后把篮子放上野餐桌。
- 刺刺先：打开抽屉找到摆餐位置；把已交付的两份食品分别安排到桌边两个席位，不能复制或再回营业库存。
- 另一个朋友仍照原单服务，无晚服务惩罚。两路都需两份明确订单和自己的操作，再铺桌布、分享，得到同一野餐食谱页和桌布；选择与实际食物留下记忆。

其他章：早餐交付→抽屉花苗→种花；冰淇淋明确订单＋可选杯装口味委托→旧食谱试味线索→品尝→挂旗；汉堡与饮品真实交付→抽屉灯→选择灯光/桌位→开灯协作；社区邀请→自由成品拼盘→摆放品尝→保存末页→开席。探索对象给具体线索、物件或新动作，不作导航装饰。

## 单归属、加工与交付

供应仅在合法落点产生唯一 food ID；起拖/取消不生成。托盘两只各三格，不设隐藏无限库存。机器、组合板、助手和交付持有真实实例。配方完整输入才能启动，原子消耗输入产生一份输出；器具自动放置也有实例。READY不烧焦，取走释放设备。

加工/助手/交付由唯一有效游戏时钟推进。启动绑定输出盘与容量预留；切台、换盘、旋转、刷新不改绑定。机器动画不能完成任务；有效接收阶段才移交食品与活动进度，重复指令/读档不重复奖励。暂停、帮助/显式教学、后台停止时钟，不补离线时间；普通参考/编辑便签不中断其他工作。

已交付食物从营业库存移到活动持有物：品种、数量、状态一致，可摆放/品尝，不能重回供应。作品保存仅是图文记忆，不创建食品。品尝改变该实例状态；记忆保留实际作品组成和位置。活动、奖励、探索与记录有界。

大咪同时一个动作、有界队列；助手仅拿苹果/香蕉，最多两份，原子预留，取消归还/释放；不读取订单答案，不自动完成整单。只有交给大咪才有便签表达尝试。词块独立ID，a/an/one/two/and有限语法，大小写/标点归一，incomplete/outside/结构调整/世界受阻分别反馈。

## 自由营业与重玩

菜单可选已介绍内容，主题只过滤新任务池，seed/cursor保留；新任务数量/设备/原料可达，最多两客。停止接客后保留已接单、食品与加工，允许做自由拼盘和作品，主动收摊回院保存。重新开店接续同一厨房；重玩活动另起run，不重复累计礼物，不清除过去作品与历史帮助。

## 无死局与支持

设备满、两盘满、助手预留、错误成品均有取走/撤回/放回/确认收起及恢复路径。成品不能还原原料；错单整盘保留。支持策略不裁剪错误选项，也不替玩家选客户；双客必须明确目标。

重听不惩罚；图片/字幕/示范/错误解释记录为支持，不能洗白。发音开发版未审核，播放事件只证明播放。小游戏/教学库存隔离，拼写与结构不锁活动。不能把纯操作错误写成英语错误。
