# 游戏设计 · 柜台服务与英语协作


**当前 M2.2 合同（2026-09-21）**：点击优先；单水果点食品→送餐，果汁点机器→水果→启动→送餐。机器/制作台就是操作入口，非教学目标器具可由规则登记自动就位。启动时绑定目的盘及一个容量预留；成品按有效时钟产生并送至绑定槽。选盘、切台、刷新不得改变绑定；容量异常时成品留出口，允许就近接取/取消/退料，禁止偷偷换盘。煎制中间产物可送到明确绑定的组合台，不能自动选配料或客人。

自动化只搬运，不读取订单答案。双客送餐显式选目标；错误物品保留，送餐按钮不按答案启用。盘中原料首点立即选中、同实体双击退回、单点后就近撤回；拖动/多指/取消清双击候选。成品确认收起且可恢复，不逆转成原料。教学中实际选择可落入本次真实配方，意义呈现与尝试分别记录，不能弹窗选完再强迫选同一份。

新无尽资料有明确的小菜单介绍和营业间隙扩展机会，依次介绍香蕉和基础果汁，不解锁全部未教食品。菜单、语言复杂度、支持、并发分别控制，seed/cursor/旧任务和物品保留。先固定容器练口味、再固定口味练容器、后数量配料；短请求未表达项由已介绍菜单约定承担。
版本：v0.5，2026-09-21。当前规则合同为下方M2活动、制作与学习规则；M1章节明确保留为历史。实现和验证状态见STATUS，数值不代表儿童验证结果。

## 1. 玩家角色与核心循环

狸花猫是主角与小主厨；玩家帮助它理解请求并操作食材、安排制作，不是需要虚拟摇杆控制的玩家化身。首版没有地图行走、角色碰撞或双人联机。

听请求 → 选择准备顺序 → 拿取/加工/组合 → 交付 → 托盘腾空 → 接待下一位。

主要选择是先做什么、如何利用机器等待、怎样使用有限托盘、什么时候请小猫帮忙。英语决定需求与取料内容；加工和占用规则决定怎样完成工作。不能用答题正确后播放固定动画代替这个循环。

## 2. 代表性双订单

A 要 Apple juice, please.。玩家把苹果与空杯放到果汁机对应位置，启动加工。B 要 An apple and a banana, please.。玩家利用机器运行时间准备水果并先交给 B，再将做好的果汁交给 A。

也允许等待果汁后再做水果，或先请小猫取料。所有能满足订单的合法顺序都有效，胜利条件不检查参考解法步骤。交错准备与串行准备应产生真实等待差异，而不是只更换提示文字。

## 3. 柜台容量与物料

| 对象 | 首版配置 | 规则 |
| --- | --- | --- |
| 接待位 | 2 | 入门只激活 1 位；背景排队角色不产生隐形订单 |
| 原料格 | apple / banana / bread 各 1 | 供应不限，仅成功放到合法目的地时创建一份原料 |
| 空杯取用位 | 1 | 空杯直接放到果汁机杯座，不做杯子堆叠 |
| 果汁机 | 1 | 苹果输入、杯座、单批加工；完成后不取杯不能开下一批 |
| 烤面包机 | 1 | 一片输入、一份出口；未取走成品时设备占用 |
| 托盘工作位 | 2 | 每位固定承载 1 只托盘，不额外增加缓存空间 |
| 托盘 | 2 | 每盘最多 3 份；一个水果、一杯果汁、一片吐司各占 1 份 |
| 重新准备入口 | 1 | 清理不需要的物品，不存储或返还成品；清理成品须确认 |

每个订单必须在一盘内完成，总份数不超过 3；首包同类水果最多 2 份。没有一张订单必须同时占两盘的要求。空白柜台不作为无限储物区，合法落点短暂显边。

食物、杯、托盘、订单和加工任务使用独立 ID。一个食物仅归属于一个托盘槽位、设备或助手任务；拖影不复制实体，落空保持原归属。预览合法落点不能按订单答案筛掉所有错误选项，否则会泄露答案。

## 4. 配方与设备

| M2 配方 | 真实输入 | 行动与输出 | 有效游戏时长 |
| --- | --- | --- | --- |
| 水果 | apple / banana | 按请求装盘，不生成额外商品 | 无等待 |
| 苹果汁 / 香蕉汁 | 对应水果 + 空 cup | 启动果汁机，水果消耗，原杯成为对应果汁 | 5 秒 |
| 香草杯 / 香草筒 / 草莓杯 | cup+vanilla / cone+vanilla / cup+strawberry | 冰淇淋台启动，完成后进绑定盘 | 1 秒 |
| 两球 / 香蕉配料冰淇淋 | cup+vanilla+strawberry / cup+vanilla+banana | 数量、口味和配料实际进入成品语义 | 1.3 秒 |
| 芝士 / 蔬菜三明治 | bread×2+cheese / bread×2+lettuce+tomato | 组合板盖合，一份成品 | 1.2 秒 |
| 饼类加工 | patty | 煎台生成 cooked-patty | 3.5 秒 |
| 汉堡 / 芝士汉堡 | bun+cooked-patty+lettuce+tomato / bun+cooked-patty+cheese | 组合板组装，一份成品 | 1.2 秒 |

内容唯一源为 `src/content/recipes.ts`。输入顺序与无关摆放顺序不判错。器具须有真实实例；M2.2非目标器具允许规则自动加入；成品内部配料不占额外成品槽。以上是玩具化配方，不是儿童使用热源的教程。旧“果汁机不接受 banana”限制被本 M2 明确替代。

**保留的后续候选**：bread→toast 与 4 秒烤面包机仍是有效设计，尚未在本 M2 实装；不能据此声称已完成吐司，也不删除该需求。M2 四类食物的工程验收不依赖它。

设备状态为 EMPTY → LOADED → PROCESSING → READY → EMPTY。LOADED 可取回原料，开始加工需输入完整且无旧任务；重复启动不会创建第二批。READY 成品不烧焦、不变质，取走后释放设备。

加工完成由游戏时钟推进规则产生，不由动画回调决定。暂停、帮助、教学和页面不可见时，全部加工及助手计时暂停；回来不补算离线时间。普通拖动和编辑便签时，其他任务可以继续。

## 5. 订单与交付

订单经历 ARRIVING → REQUESTED → WAITING → FULFILLED → LEAVING。每位客人同时一个稳定请求，刷新不换题。初次英文播放需用户激活声音；第二位到来不打断正在播放的请求。可点客人切换前景请求、重听或求助。

正式交付默认点就近送餐按钮；单客明确送给该客，双客先选目标再确认，按钮不检查答案。点客人始终只选客/重听，不受隐藏选盘状态改变。整盘拖到客人仍为等价交付。拖单个食物是在编辑托盘，不暗中交付。空盘/缺份提醒不计语言错误；明确交付时品种或数量不合，最多记为请求匹配失败，不能自动诊断听力或语法差。

匹配比较产品 ID 与数量的多重集合，不比较托盘排列或制作顺序。必须完整匹配，不能自动移交给另一客人，不能只吞掉正确部分。完成原子提交订单、消耗食物并腾盘，同一订单不得重复完成。

客人拿走食品，小猫推回空盘；短回位期间只限制这一托盘的命中，另一盘和设备继续可操作。不能一边显示未送出的食物，一边允许从空盘再次交付。

不匹配时保留成品和订单，给一条差异，例如“这位客人要果汁”。差异可能揭示目标，记入本题帮助记录；修正后的成功不能当第一次无提示完成。

## 6. 小猫助手与便签

直接取料始终可用。玩家可选托盘、点小猫便签、用词块提出取料请求，再明确点击“交给小猫”。助手首版只取 apple/banana，最多两份，不自动加工、识别客人或完成整单。

候选表达：An apple, please. / One apple, please. / Two apples, please. / An apple and a banana, please.。便签不展示可直接照抄的完整目标答案；教学时另作明确示范。

M2 动作按距离和阶段计时，猫同时执行一个动作计划，可有有界队列；不再用固定 2 秒压缩全部取料。提交时原子核验空闲与托盘容量，并预留全部所需槽位和物料身份；空间不足不取一半。助手持有物料直到完成，目标绑定提交时的托盘，不随当前 UI 选择改变。

合法表达按其语义取料，不先与客人答案比较。可以取出暂时不满足订单的东西，之后自己调整。助手忙或空间不足是世界受阻，不是英语错误。

取消编辑不记提交；已提交取料可取消，归还未加工原料并释放预留，保留历史语言记录。存在预留的托盘暂不可交付，允许等候或取消。完成由游戏任务时钟触发，动画仅表现动作。

## 7. 语言判定与证据

顾客请求是理解任务，便签是表达任务，配方是操作知识，备料是拼写任务，不能全部汇成一个正确率。

便签用有限内容语法：a/an/one 加可数单数；two 加复数；两个单份短语用 and 连接；please 位置按已登记变体。大小写、句末标点和合理逗号规范化。两块相同文字有不同 token ID；一块不能用两次。不同排列的苹果和香蕉表达可以映射同一集合。

场景请求允许自然省略句，不使用统一“少于六词不完整”规则。One apples 可以给出已教范围内形态提示；未覆盖表达标 outside，不泛称错误英语。解析返回语义，由应用层检查任务归属与实际执行条件。

toast、juice 的可数性不按 apple 套用；菜单首次说明 toast 是一片、apple juice 是一杯，首版不用 two toasts/two juices 作基础标准答案。所有材料需真实教研审核。

| 条件 | 内容 | 记录 |
| --- | --- | --- |
| 首次教学 | 物品、目标词、声音、完整演示 | guided / demonstrated |
| 辅助练习 | 文字、数量图或目标提示 | assisted，列明支持 |
| 独立听请求 | 不显示目标图/答案文字，可重听 | 记录独立条件尝试，不称掌握 |
| 主动帮助 | 开字幕、解释、演示 | 当题支持保留，不能撤销洗白 |
| 回访 | 改变客人、位置、顺序和组合 | revisit + 实际支持条件 |

重听不扣分，也不自动降低证据等级；文字/目标图/示范会改变口径。开发 TTS 或播放失败不能证明正式独立听力合格。手速和加工等待不进入英语能力评分。

## 8. 备料拼写与小食谱

开店前或主动打开食谱可学习 apple/banana/bread，按意义或声音进行字母点击/拖放拼写，支持先讲意义、辅助、独立尝试。新词不能直接连续出题。

历史M2教学展示不产生库存，M2.2将适合的选择接入真实制作；两类小游戏与营业库存隔离，返回保留营业世界与时钟。教学实际选择只触发一次且占正常容量，错误备料也保留；设备忙或满位不产生语言尝试。自由原料格始终可取，不要求每次补料先拼写。

小食谱只有当前几页与练习，不扩成课程大厅。提交拼写/便签使用明确按钮；拖动、重排和空白草稿不计错误。

| 场次 | 内容 | 订单数 / 同时接待 | 新选择 |
| --- | --- | --- | --- |
| S1 第一次开摊 | 整果、单份、two、短备料拼写 | 4 / 1 | 理解数量后真实装盘，不靠复制任务 |

新设备第一次出现先暂停讲解，不同时塞进另一条未学请求。订单来自人工编排或有限校验变体池，seed/variant 保存。重玩显式换变体，不能随机产生缺音频、缺原料、超容量或尚未教过的新结构。

胜利条件是该场有限订单均完成；没有强制先后步骤。结束停止新到客，在原餐车内短暂小结，允许下一场、重玩或离开。份数和场次数只属于首包，不设为全产品上限。

## 10. 无惩罚失败与恢复

原料加工前可以退回，成品可以换盘或确认清理。加工后不能把果汁还原苹果或令时间倒流；清理入口永远可用，不要求先有空盘。两设备 READY、两盘已满或助手预留时，始终有取走、取消、退回或重新准备的路径。

首版不做全局时间回滚。“撤回”用于便签草稿和未提交拖动；实际制作错误通过重新准备修正。交付后不可回退重复完成。重新开始整场须确认，不能擦除已有帮助后伪装同题首次独立。

默认不做耐心条、烧焦、限时淘汰、扣生命、清洗盘子或金币。食物错误不以顾客羞辱玩家表现。声音/图像/存储故障单独提示，继续或重试不会复制食物和订单。

## 11. 趣味验收

验收看玩家是否主动安排并行工作、看懂加工产物并根据后果调整。串行与交错路径都可完成，不强迫最优解。

禁止：配方表加提交按钮代替制作；单击食材直接自动完成订单；同一客人永远固定答案；每单弹大结算页；通过缩短倒计时掩盖内容单薄。

如果没有惩罚仍完全没有可玩性，先修操作、流程与反馈，再考虑扩关。图好看、使用引擎、测试通过均不能单独证明好玩。

## 历史 M1 三模式合同（被 M2 活动与支持分离替代）

首次默认 guided：一客一盘单果目标，场内拿放演示先于孩子操作；下一次明确选择可体验预放杯的果汁引导，标记 guided-preparation。practice：一次一个目标，苹果、香蕉、two、组合、苹果汁有限内容逐步尝试，随时图片/重听帮助。service：保留双单双盘并行与可选词块。三者共享食品、配方、任务和交付。模式切换保存各自未完进度，重玩单独确认；见过的解释、图示与示范跨模式累计，不因刷新洗白。独立听请求必须显式撤去图示、变化座位且语音有成功播放记录；开发语音不代表合格听力证据。


历史 M1 有限任务为 guided 的 apple/juice 两个重玩变体、practice 的 5 个顺序请求、service 的 fruit+juice 双并发；`requestsFor` 是内容来源，不另建关卡页面。首次 guided 固定 apple，后续换模式可选有限 variant；service 交换请求与座位，practice 重玩交换起始单果与后续顺序。辅助示范的历史跨模式保留。尝试同时记录 condition（guided / assisted / independent-condition）、visit（first / revisit）和 audioQualified=false；独立条件也不等于已通过听力测评。新知识示范不产生用户尝试，图片助手不冒充词块语言提交，未齐/拖空/忙碌不算语言错误。

## 12. M2 活动、制作与学习规则

故事/无尽/教学是会话目的，guided/practice/service 仅保留为历史教学和营业基础能力，不作为首页主模式。支持策略为示范、图片、较少辅助，仅影响语言提示；营业负荷另选一次一客或两客，不替孩子选择食物/客人。普通点击原料放到明确选中的备餐位置；多个合法位置需要选择。点击选中盘中实体立即显边，再双击同一实体退回原料；也有就近移除。拖动/多指/cancel 会清除双击候选。成品清理先确认，短期回收可恢复原成品，不逆转配方。

有限模型：Recipe 定义合法输入多重集与成品语义；Station 是果汁机、冰淇淋台、组合板、煎台。果汁为 apple/banana+cup→对应 juice；冰淇淋显式 cup/cone+vanilla/strawberry 球（1–2）+可选 banana；三明治为两片 bread+cheese、可选 lettuce/tomato→盖合；汉堡为 bun+经煎台处理的 patty+cheese/lettuce/tomato 中的登记组合。加工/盖合均有任务、剩余时间与真实输入消耗。成品包含组合特征但只占一个盘槽；无关输入顺序等价。器具预置必须生成有来源的真实 cup/cone 实体。每次仅呈现当前食谱原料。

动作计划保存归一化锚点、阶段时长/经过时间和绑定物料；取料与交付排队，教学是同调度器的可取消表现任务。规则在明确的放下/接收阶段转移归属；动画读取阶段，不回写判定。暂停/读档/旋转沿同一计划投影，跳过教学从当前位置回位。

内容驱动教学：每个请求关联词/表达、意义图片与发音、示范步骤、支持条件、可接受语义与差异反馈。新知识先看/听/做，学习目标与设备并发分别增长。历史接触只标回访；本题 support 持续到结束，重开同题保留，真正新题不复制历史帮助。独立听音隐藏目标图片/字幕，物料位置不编码答案；重听不记错误。词义、听力、拼写、基础结构和操作分开记录。

无尽采用保存的 seed/cursor，避免连续相同请求；只从已介绍、原料设备和容量可达的登记请求池选取。最多两客、活动订单有界，完成历史压为计数与有限观察，不堆已完成实体。收摊暂停且能继续。小游戏使用自己的确定性回合状态，不修改营业世界；重复字母独立 ID，示范/部分/独立支持按题保存。


## M2.1 教学与回访细则

每个实际单元按“一个图音意义→一次可点选的名称/份数/组合尝试→当前配方一步→在餐车实际使用”展开。没有看完的面板不能算教程完成，播放成功不能算理解。已介绍的食谱可从教学入口回访；少些帮助是可选的后续条件，同一题看过的图和答案不会因切换、关闭或刷新变回独立条件。重听不记语言错误，有限句法仍由phrases判定；数量和and只解释当前可见情境。

WordSpell按已介绍词、字母基础与实际支持量选池：示范保留模型并固定除末位外的字母，部分补全固定隔位，自己试无固定字母；字母托盘本身如实记letter-bank。新手限制负荷，选择短语基础后保留ice cream等词界，空格不可编辑但参与判定。可点选空位、撤回、换位或拖动，重复字母各有ID。

食物找朋友是逐题选择：听词找图、看英文找图、识字后中英文字配对；不是多项连线。已开始播放即可直接选图，不能要求额外点喇叭。选项从活动词池按帮助量抽取并换位；缺实际播放的尝试记录audio-not-observed，开发音频始终不标为已听审。

小游戏选择页保留各活动继续入口；展开“换帮助或玩法”可按新设置开组，明确确认替换该活动草稿，未完成题的已用帮助携带至新组，不清除营业库存。无尽的菜单准入只表示介绍/操作经历，不表示英语掌握。
