# 游戏性设计 · 连续餐车

本文件是2026-10-13唯一现行游戏性合同。目的：每个动作改变看得见的食物或局面；真实接收推动短波次，五章持续增加选择，故事不断在菜单间打断。此前手动流程合同归档，现有规则的守恒与学习边界保留。

## 核心循环与统一输入

动物自然走到餐桌→完整英语请求首次自动播放、字幕持续可见→玩家点物件，或点选后点目标/宽容拖动→实际食品明确送到目标朋友→规则接收→朋友感谢与品尝、鲜明音画反馈→下一客/下一波→章奖励和自然过场。朋友只在有效接收后得到食品，错误整份留在厨房。

水果点一下拿起再点朋友。设备旁原料一次放入实际位置：冰淇淋先容器、再口味，可继续加合法球/配料；三明治实际叠层，第二片面包自然盖合；汉堡由真实煎熟肉饼、圆面包与配料合成。成品点选后明确送给朋友。只有煎锅3500ms和果汁5000ms保留实际开关与加工钟。没有设备轮换、交付模式、接好/盖合确认或强制拿放循环。所有输入使用同一命令、同一判定。

食品选错可放回或收起后恢复，未加工原料可拿回；成品不反向变成原料。双客接收目标明确，顺序自由。加工、已接订单和预留不会因策略切换、刷新、转屏或声音失败消失。默认没有离线补钟。

## 五章、短波次与成长

| 章 | 可观察的局面变化与真实决策 | 高潮与过场 |
|---|---|---|
| 早餐派对 | 两波连续来客，第一波苹果/香蕉，第二波双份苹果与苹果+香蕉。先理解单件，再按数量/组合实际准备，水果以外设备退居探索 | 每次接收立即反馈，真实四次接收形成早餐席，花与食谱页作为场景奖励，自动进入甜点 |
| 冰淇淋狂欢 | 先蛋筒香草与杯装草莓，再双球与香蕉配料；最后朋友开放选择一杯合法甜点。杯筒、球数、口味和配料直观改变成品，错误保留 | 实际不同甜点自然并列和品尝，彩旗与页奖励自动出现；没有比较按钮前置 |
| 野餐接力 | 两位朋友同时请求芝士/蔬菜三明治，玩家真实选择先做/先送谁。首份有效接收决定路线，点击角色/错误交付不能定分支。兔兔路线随后实际补一份三明治和一份水果到篮子；刺刺路线利用两份已接食品原位分餐 | 满篮由规则摆桌；刺刺路线保持原有两份餐。两路实际食品和分支留在记忆，桌布/奖励等价，自然去黄昏 |
| 黄昏餐车 | 两波同时需要汉堡和饮品：芝士汉堡+苹果汁，普通汉堡+香蕉汁。煎锅/果汁机/组合板同屏，玩家可在煎制中准备杯、水果和另一料理，决定服务顺序 | 两波真实接收后朋友自然带灯，灯与晚餐席亮起，进入嘉年华 |
| 美食嘉年华 | 两位老顾客自然回访，需要来自本轮实际野餐路线与已接食品。开放类别请求允许合法替代；玩家真实制作、自由拼盘和分享，长辈与额外探索自选 | 两位真实接收后自动品尝并保存实际作品、庆典和末页；保留作品/回访事实，随后继续自由创作，自由厨房仍为自选入口 |

波次是配置与领域状态，不是计时压力。每章一个当前目标，显示波次图点和需要的实物，非关键食谱/练习/回看退到暂停或自主探索。收尾无需找完成、返回或下一步。最后一章留在庆典现场供继续玩。

## 单一事实源与连续进度

新增有版本的连续故事状态记录当前波次、阶段、有效时钟截止值、完成章节快照；状态有界、确定性、可恢复、幂等。配置声明订单池和波次，订单判定仍是 REQUESTS 的产品/数量多重集合，不另写一套答案。只有实际 receive 转移、合法开放接收、篮内实物和真实分享收据满足条件才可推进。

自动品尝只作用于实际已接收食品，自动保存只截取实际作品，自动奖励必须通过规则 readiness。这些是角色后果，不产生用户语言尝试、帮助洗白或额外食品。波次/章切换等待在途交付安全边界；多余库存和合法加工保留进入后章，不静默丢弃。历史章节快照是记忆，不能复制成营业库存。表现回放、低动态、静音、取消音频、刷新均不重复消费或授奖。

兼容本仓库已有存档：保持schema7的库存/任务校验，连续字段显式校验。未完成旧章保留已接请求、食品、加工、历史支持；只在安全边界启用后续连续合同，不凭空补旧章的新波次或奖励。已完成旧章不重新锁住；历史材料仍保留原版本。不存在其他旧仓库导入。

## 开放厨房与学习边界

自由厨房一次进入即可营业，菜单/主题/帮助/客流在暂停中自选；已接请求不随菜单重写。可停止接客并真实制作最多三份作品、摆放、品尝、保存/修改，回看不创建食品。十类游戏、50食品/120概念继续正常可达：听音、配对、拼写、数量、组句、寻物、记忆、归类、布置、动作剧场；不锁主线。帮助/示范/支持历史不可通过撤回或刷新清除。

实际交付或便签才记录语言尝试；自动语音、品尝、分享演出、奖励和保存记录操作/记忆。落空、容量、预留、设备忙、存储/音频失败不是语言错误。图片/字幕可见按真实支持记录，不把播放或速度当听懂。开发声音未听审，真人/儿童/实体设备/教研/权利分别待验。
