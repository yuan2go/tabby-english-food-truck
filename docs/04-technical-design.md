# 技术设计 · 独立餐车游戏


**当前 M2.1 合同（2026-09-21）**：沿用锁定栈；内容显式登记名称/中间产物/成品/请求/剧情提示音频。前景播放采用可取消完成结果，组件不各自争抢。schema4明确迁移schema3世界；小游戏按活动保存并保护旧原文。
版本：v0.3，2026-09-21。当前M2在既有React/TypeScript/Vite/Phaser上实施；以下通用不变量继续有效，M1保存/构建段落保留为历史，M2实现决定见末节。运行证据和审核状态见STATUS。

## 1. 技术选择

采用 Phaser 为核心的二维游戏客户端，TypeScript 严格类型与 Vite 构建；React 仅承担新写的启动/设置与必要无障碍 DOM。正式画面由游戏场景组织，不由 React 卡片拼装。没有服务端、账号、联网多人或实时 Provider。

参考 Phaser 官方 React/TypeScript/Vite 模板的宿主桥接和构建方式，不复制其示例 UI，不以官方模板声明代替质量保证。具体 Phaser、React、Vite、TypeScript 版本在初始化时选择兼容组合并锁定；先完成目标浏览器冒烟，不在本文虚构已安装版本。

默认不引入物理系统、ECS、数据库、全局工作流、状态库或通用编辑器。游戏只需要明确的设备/订单/物品规则，不需要实现完整厨房模拟。模板自带遥测须检查并关闭不需要的部分，许可证和素材分别登记。

## 2. 分层与建议落点

实际 M0/M1 采用 src/app、src/game（场景/输入/布局）、src/rules、src/content、src/platform，以及 tests/e2e；下表保留职责划分，未建设独立通用 view 框架。

| 层 | 建议目录 | 责任 |
| --- | --- | --- |
| 新应用宿主 | src/app | 启动、设置、游戏实例生命周期、可访问 DOM，不持有第二份订单状态 |
| 游戏场景 | src/game/scenes | 餐车、加载、场内 HUD 与短结局；主要流程共用同一餐车 Scene |
| 对象与表现 | src/game/view | 客人、猫、托盘、机器、文本、命中与动画；只投影规则状态 |
| 规则模块 | src/rules | 订单、配方、归属、容量、任务时钟和交付，独立于引擎/DOM |
| 语言与内容 | src/content | 食品、配方、请求、词块语法、教学与场次变体；有限校验 |
| 平台 | src/platform | 保存、音频、资源、可见性与异常，不引入线上服务 |
| 必要验证 | tests / e2e | 规则测试与真实 HTTP 浏览器操作，不用大量快照替代行为 |

React 与 Phaser 通过小型有类型接口通信：开始/暂停/设置/命令和只读通知。不建立可随意发事件写状态的全局总线。场景卸载必须解除订阅、指针捕获、音频、计时和动画，避免重新开始后双重处理。

## 3. 单一规则事实源

统一链路：触控/点击/键盘 → 标准游戏命令 → 校验与规则转换 → 原子更新 GameState → 场景与语义 DOM 投影 → 声音/动画。

游戏业务事实保存在一个 GameState。Phaser display object 的坐标、React state 和动画结束事件都不能单独决定库存、任务完成或语言结果。规则不需要从旧仓库迁移，在本项目全新实现。

推荐状态包含 schemaVersion、contentVersion、sessionId、runId、revision、场次与 seed/variant、订单、物品、托盘槽位、设备任务、助手任务、帮助和有限学习记录。UI 的选中、指针坐标、词块草稿和短暂拖影另存，默认不持久化。

revision 只在离散业务变化时递增，不每帧增加。命令包含稳定 commandId 与当前 runId；异步任务回执须匹配 jobId/epoch，旧场次或旧任务回调不得更改当前世界。短小的去重回执即可，不要求全量命令日志重放平台。

## 4. 必须实现的规则

- 食物只属于一个 owner/location；槽位容量和预留一致，拖影不是一份新食物。
- 原料供应格可以无限取用，但只有成功目标落点才创建新 ID。起拖、取消或重复事件不生成物品。
- 果汁机输入登记水果与空杯，启动时绑定本批物料；完成后水果消耗、原杯含对应果汁，未取杯不能开新批。
- 所有组合配方显式消耗输入并生成一份产物；后续吐司候选同样不能同时保留原片和复制成品。
- 助手取料一次预留所有槽位，job 持有原料；取消归还/释放，完成原子转移，目标不随 UI 选择变化。
- 交付检查当前客人和托盘内容的多重集合，完全匹配才更新 fulfilled、移除食品并释放托盘；重复交付幂等。
- 做错的食品可移动/清理，清理只减少物品，不变成隐藏缓存或奖励来源。

规则查询与执行必须共用约束：UI 展示可操作位置，实际提交再次检查；不要在 JSX、Scene 或测试辅助脚本中各写另一份配方/订单逻辑。

## 5. 时间与异步任务

只有一个游戏时钟。加工和助手任务保存剩余有效时间或 startGameTime/duration，不用真实墙钟推算离线收益。前景可运行状态下推进时钟，到期由规则完成任务。动画显示进度，不产生任务事实。

暂停、帮助、小食谱教学与页面不可见时同步停所有任务；恢复只继续剩余时间。普通拿放/便签编辑期间允许其他任务运行。页面恢复后丢弃后台大 delta，避免瞬间完成全部设备。

同一帧多个到期任务采用稳定顺序处理并维护原子归属；设备任务到期且发生用户操作时，先按统一入口结算已到期任务，再按当前状态处理命令，不让视图各自竞态更新。

助手执行中的物料/槽位预留必须进入快照。读档后从任务状态恢复，不再次生成原料或重收一个便签。禁止 setTimeout 的残留回调在重开后继续完成任务。

## 6. 语言判定与记录

RequestSpec 保存期望商品集合、场景语音、支持资源、学习目标和当前练习模式。PhraseSpec 保存 token ID/文字、受支持句型与语义。显示英语文本不是用来硬编码唯一字符串判分。

流水线：检查词块归属和唯一性 → 规范大小写/标点 → 有限语法解析 → 返回取料语义 → 检查助手/容量 → 执行。结构有效不等于符合某位客人订单；便签不预判客人目标，允许孩子试不同方案。

结果至少区分 incomplete、language-adjust、outside、world-blocked、request-mismatch、completed。内部命名可不同，但不得把世界阻挡记为英语错误，也不能把未覆盖表达强判错。

学习记录至少含 activity/runId、目标维度、输入/语义、首次/重试、support、audioId/版本/实际开始与中断状态、结果与设备动作原因。录音未审核和开发语音单独标记。子事件数不当作学习题数。

帮助按本次题目/尝试序列累计：看过答案、示范或错误后的目标解释不会因撤销、关闭再开工具或刷新而消失。同一局重开可以是新 run，但再次遇到相同内容不能伪装未见过的首次独立测试。无个人身份跨设备追踪要求。

## 7. 内容与有限变体

食品/配方/句型/场次用有类型对象或校验 JSON，不建设可视化编辑器。订单生成只选已校验的有限集合，不依赖模型现场出题。

加载前检查引用存在、商品可制作、数量/托盘容量合法、词块无重复 ID、所有已用请求具备资源或明确降级、必要知识有教学入口。seed 固定、variant 与内容版本保存，刷新不能偷偷切换新题。

一单的上限在内容与规则双层验证，不能仅用 UI 禁止。派生效果和参考答案不保存在图片里，不从任意远程 URL 载入未审核素材。

## 8. 输入、表现与无障碍

用 Phaser 指针输入归一鼠标和触摸；命中坐标依照实际 canvas CSS 尺寸、缩放、相机和安全区换算。选择/拖动只影响临时视图，释放在目标内才提交命令。按最终 CSS 尺寸验证命中，不能只看设计分辨率。

逻辑位置与展示锚点分离。横竖屏切换只重排 view，不改变托盘归属或当前订单。顶层弹窗吞掉下层输入；cancel、多指、移出、失焦、后台释放未提交手势。便签通过拖入/按钮两种方式编辑。

提交后表现消费短事件，不等待 animationend 保存。允许较新的命令取消或合并旧 cue；低动态模式直接显示稳定结果。设备 PROCESSING 动画服从任务进度，不能自己完成任务。交付短暂回位只锁对应视图，状态不得被重复点击消费。

语义 DOM 与 canvas 可见对象共享命令和禁用原因，键盘不调用后门完成操作。焦点可见，模态收起返回触发对象，屏幕阅读器不暴露独立题目标答案。未实现的辅助技术支持应明确记录，不因用了 React 就宣称可访问性完成。

## 9. 新存档，无旧包兼容

当前 key 为 `tabby.foodtruck.save.m2`，长期成长与设置使用独立前缀。M1 的 `tabby.foodtruck.save.v1` 原文留存，首页明示新故事与导出位置；不把旧 M1 订单推断成新章节完成。采用受校验快照，不要求完整事件溯源或其他项目 codec。

快照保存完整当前归属、订单、剩余任务时间、预留、seed、support 与有限观察记录。实际变更后保存；加工中的进度可每约 2 秒做轻量检查点，恢复最多回到最后成功检查点，不承诺崩溃零损失。

写入新有效快照前保留上一个可读版本，成功后清理；不能凭未验证 projection 初始化库存。加载时校验版本、字段类型/大小、ID 关系、数量范围、任务与所有权一致性。未知/损坏版本保留原文并允许导出/明确重开，不猜成绩，不直接覆盖。

本地存储失败提示本局临时运行并继续，导出应含内存状态；存储缺失不阻止进入无进度新局。提供清除本项目记录的确认操作，不触碰其他项目键。具体字节/事件上限在实施时写入配置和测试，不能无界增长。

## 10. 音频、资源与性能

首个手势激活音频；一个前景英语通道、有限音效与背景音乐。新重听取消旧播放；后台暂停，回来不连续补播。实际播放状态与来源要可观测，失败提供重试或文本帮助，不依赖客户端密钥。

唯一资源清单登记实际 hash/字节/尺寸/Alpha/来源/审核。按启动关键资源、当前场次和延后资源加载；失败重试不重置订单。新资源与代码版本一起发布，缓存不得混用旧请求语音和新订单。

初始预算建议：常规设备以接近 60fps 的反馈为目标，较低性能设备允许降效果但保持操作响应；主要输入响应目标 p95 <100ms，首可玩资源压缩后目标 ≤5MB、全首包 ≤15MB。它们是待测预算，不是已经达标。记录设备/网络/采样路径，超预算先压缩贴图、减粒子和避免多余重绘，不缩小关键文字与命中区。

React 不接收每帧坐标，设备进度由 Phaser 表现更新。动态纹理/音频实例、事件订阅和任务数量有上限。选择支持的 renderer 后在实际设备检查，不能默认所有 WebGL 不可用场景均有现成降级。

## 11. 构建与发布

新工程实际建立 package.json 与锁文件后再登记真实 npm 命令。预计需要 install/build/typecheck/unit/browser/resources 几类命令，名称由实现决定；文档初始化阶段不伪造 npm test 已存在。

静态 dist 发布到经授权的 HTTPS 托管，检查根路径/子路径、刷新、缓存、资源与音频。GitHub 私有仓库和公开游戏是不同权限，不自动改变仓库可见性或替用户创建第二个站点。

必要测试覆盖业务规则、当前场次、同屏并行、恢复和真实输入，详见 05。发布版本记录代码 SHA、内容与资源版本；回滚要一致，不能回滚 UI 却留下不兼容存档写入器。

## 历史 M1 升级决策

schema 2 / m1.2 定义模式、有限内容变体、累计支持与教学阶段；v1 保留原文导出并明确重新开始，不猜测迁移成绩。规则唯一持有世界；按模式保存仍受同一校验器验证。运行层按稳定 ID 局部同步；每帧仅任务倒计时结构共享，离散事件同步 UI，保存合并并在生命周期退出刷盘。

Phaser 3.90.0 官方源码已定向核验：不猜配置 resolution；采用 Scale.resize + CSS display size + 相机 zoom 的明确定义物理缓冲，游戏/DOM坐标保持 CSS 像素。Text.setResolution 控制文字纹理。DPR 上限与总像素预算及低画质选项限制成本，记录实际数据。


历史 M1 保存入口为 `tabby.foodtruck.save.v1`（key 是命名历史，不代表 schema），另有 `.previous`、`.guided/.practice/.service`。同一控制器只持有一个活动世界；非活动玩法是经校验的序列化快照，拒绝持久存储时本次切换可用内存快照恢复。错模式、坏档和未来版本先阻止覆盖并允许导出，明确重开才清理对应坏数据。

每帧 advance 只复制小型时钟/任务分支，食品与证据共享直到真实事件；离散命令仍克隆一次。场景持有稳定图片/文字/徽标，取消旧 revision 的表现不会反写领域。取消、卸载、读档/重开、方向变化清理捕获/旧表现。保存仅离散操作、2秒检查点与生命周期刷盘，音频事件不单独同步写存储；不存在每帧 JSON 签名或整场销毁。

`ForegroundAudio` 持有所有前景播放器、AudioContext、gain bus、循环与短节点。语音 epoch 防旧回调；状态转换去重触发提交成功/完成声；刷新后的既有任务不补奖励声。所有任务由领域有效时钟推进，语音/动画回调不判单、不奖励、不写库存。

Vite 构建注入真实 `git rev-parse HEAD`、dirty标记、内容m1.2、资源manifest SHA-256与构建时间；暂停页和 main 的只读 data 属性可核验。部署未给出身份时保持 UNKNOWN。Phaser3.90 API依据：[Config源码](https://raw.githubusercontent.com/phaserjs/phaser/v3.90.0/src/core/Config.js)、[Text源码](https://raw.githubusercontent.com/phaserjs/phaser/v3.90.0/src/gameobjects/text/Text.js)，本地锁定源码确认没有 GameConfig.resolution，使用真实缓冲 resize 和 Text.setResolution。

图片与本地语音 URL 统一附带实际资源清单 hash 前缀，避免部署后稳定 public 路径继续命中旧缓存；源码版本与资源版本都可在运行页查看。

## M2 当前架构决定

保留锁定 React/TS/Vite/Phaser，不换引擎、不加后端或运行时模型。有限内容新增 recipes/chapters/learning；规则分 station/assembly、story/endless 与小游戏；角色调度独立于 TruckScene；首页/故事导航、教学、设置与小游戏分组件，App 只组合生命周期。

schema 3 / m2.0。长期 progress（章节/已介绍内容）、tutorials、observations、settings 与一个 active session 分离；非活动营业序列化，小游戏不复制库存。保存校验同一份 recipe/request 内容、ID、槽位/预留、任务阶段与成品特征；有界 receipts/observations/队列。M1 schema2 原文保留为旧档导出，无法可靠推断的新故事进度不猜迁移；首页明确提示新 M2 故事，旧档不覆盖；异常 M2 档须显式选择新旅程。资源按小院/活动食谱加载，DPR预算沿用。
