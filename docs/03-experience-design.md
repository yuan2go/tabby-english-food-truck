# 体验设计 · 场景、触控、美术与音频

版本：v0.1，2026-09-20。依据 [产品](01-product.md) 与 [玩法](02-game-design.md)。本文件是生产要求。当前已有餐车、道具、客人候选资源和本地开发语音，详见 [资产记录](../art/README.md)；狸花猫参考、正式听审与真机验收仍缺失。所有尺寸/时间为目标，不是已测结果。

## 1. 视觉方向

一辆真实可操作的纸艺餐车，而不是米黄色网页卡片。采用统一二维略俯视柜台与正面角色视角：人物在后，机器在工作台，托盘在近景，供应格位于手容易触及处。视角不混用写实照片、等距箱子和卡通正面贴图。

餐车轮廓、遮阳篷、木质柜台、墨绿结构与赭黄小部件建立识别；暖纸色是背景材质，不是每块 UI 的统一填充。清楚可食用的食品外形、机器过程与角色行为是第一视觉焦点。

不复制 Steam 游戏、品牌吉祥物、素材、整套界面或字体。历史页面不作为参考图。允许保留确认的狸花猫设定，不自动采用旧文件。

## 2. 首屏与主要画面

首屏就在餐车前，有开始/继续、声音选项和小型设置入口。游戏中去掉网站导航、课程卡片、长任务说明和常驻大标题。选择开始后，首次客人来到柜台，简短交代目标，不播放不可跳过的长旁白。

手机竖屏构图建议：上部为两个接待位，中部为猫与设备，下部为两盘工作位，底部为原料格。HUD 贴合边角，只放暂停、声音和有限订单进度。所有关键操作在单一可见视口内，不靠页面上下滚动。

| 区域 | 应展示 | 不应展示 |
| --- | --- | --- |
| 接待区 | 两位客人、选中请求、重听/求助 | 两个同时播音的大任务面板 |
| 加工区 | 果汁机/烤面包机状态与正在操作的小猫 | 原料/产品 ID、布尔状态或 JSON |
| 工作区 | 两只清晰可点的托盘，每盘三个可辨位置 | 另加隐藏库存或无限堆物区域 |
| 原料区 | 食材、杯子与直接触控反馈 | 每种食材一张完整信息卡 |
| 学习工具 | 按需词块便签或小食谱 | 永久占半屏的输入表单 |

360×640 是小屏布局回归起点；390×844、768×1024、1024×768 和桌面也需覆盖。目标是 CSS 视口可玩，不要求浏览器 Fullscreen API 成功。浏览器栏、系统安全区和软键盘出现不得把按钮推出可操作区。

Pad 与横屏应重新排接待/工作区，不把竖屏画面简单拉伸。屏幕变大不增加订单数量或改变规则。暂用同一场景不同布局配置，而不是独立移动端 Demo。

## 3. 信息层级与语言显示

第一眼看到客人、食物、机器；第二层看到当前选择与进程；只有需要时读句子。物品名称在教学、选中或显式帮助中出现，不在所有食物上同时显示中英文和状态。

英文请求在当前客人附近短暂显示或按模式隐藏。独立听请求条件不显示目标图片/目标词/答案数量徽标；客人外貌、座位不能固定编码食物。选中反馈只表示操作对象，不表示正确答案。

学习示范中完整句子可见，便签练习中不在上方常驻可照抄答案。打开帮助后可以显示明确文字，但记录支持。未知或播放失败要解释，不能默默把独立听力改成看图选物。

句子用清晰独立文字层。英语正文建议以 18–22 CSS px 为起点，长句适当换行；确需缩放也不挤成小字。主要目标至少约 44×44 CSS px，不仅是图片文件大；缩放后的命中区域要实际检查。颜色之外提供形状、轮廓或状态动作。

## 4. 触控与键盘

拿取有拖放和点击两条等价路径：拖动原料到目的地，或点原料再点目的地。整盘交付使用盘把手/明确盘区，盘中单个食物可独立编辑。盘把手与食物热点不能重叠到无法选择。

按下有轻微抬起/阴影；移动时跟随手指并留偏移，避免完全遮住落点。释放后成功吸附或回原位，不漂到未知位置。8 CSS px 左右的拖动阈值可作初值，需真机调整。

只使用一个有效指针；多指、pointer cancel、离开画布、旋转和后台取消未提交拖动。取消不扣食物、不提交订单、不改变语言结果。拖动结束不产生第二次点击。

设备按钮在真实可用状态下可操作；不可用要说明缺杯、缺原料或已占用。不可用与“不是当前客人想要的食物”不同，不以答案裁剪交互。

键盘可通过可见焦点选择原料、目标、机器与客人，Enter/Space 执行，Escape 取消。必要语义 DOM 与可见对象一一对应，不能在屏幕阅读器名称中提前写出独立听力答案。低动态模式保留状态和反馈，不通过纯动画传递唯一信息。

## 5. 便签与小食谱

便签是场景上的小便签板，显示当前目标托盘和少量词块，不跳转另一页面。词块点击/拖入、重排、退回均可，重复词块保持独立 ID。显式“交给小猫”才提交，编辑和不完整内容不算错。

便签打开时，普通营业仍继续；一个前景英语语音通道避免请求与词块读音相互覆盖。词块发音若揭示当前独立任务答案，需要记为帮助，不能靠声音交互绕过支持口径。

小食谱用于短学习/练习，开启时暂停营业。返回还原选中对象、托盘与机器进度；练习库存隔离。练习结果简短，不能多层弹窗叠成新课程网站。

## 6. 动作脚本与反馈

| 行为 | 可见因果链 | 时长起点 |
| --- | --- | --- |
| 选中/按下 | 阴影变化、轻抬起、目标边缘 | 80–150ms |
| 有效落点 | 物体跟随 → 落入位置 → 轻微收稳 | 150–300ms |
| 落空 | 保留本体 → 回原位 → 一次简短说明 | 150–300ms |
| 榨汁 | 苹果入机、杯就位 → 加工 → 杯内果汁上升 | 跟随 5 秒真实任务进度 |
| 烤吐司 | 面包入槽 → 加工 → 吐司弹起并留出口 | 跟随 4 秒真实任务进度 |
| 助手取料 | 看便签 → 取料 → 携带 → 放入绑定托盘 | 跟随 2 秒助手任务 |
| 正确交付 | 托盘递出 → 客人收食物 → 空盘回位 | 约 0.6–1 秒，可缩短 |
| 请求不匹配 | 客人示意/复述差异 → 托盘保留 | 约 0.4–0.7 秒，不羞辱 |

动画时长不是判定依据。状态转移后，表现按事件和最新 revision 消费；旧动画结束不能覆盖新的食物位置。只对正在交付的盘短暂限制输入，不能为一个庆祝冻结整辆餐车。

小猫是有行动的角色：待机观察、看向客人、读便签、取料/携带/递交、轻微受阻、庆祝。M1 至少让取料与交付有连续姿态，不接受静态猫贴图左右滑动就算全套动作完成。可用 sprite sheet 或合适的骨骼/分层动画，按实际方法报告，不伪称已制作逐帧素材。

## 7. 狸花猫与资源生产

猫必须是棕灰底色、深色虎斑、金黄色眼睛、浅口鼻。灰项圈与白色圆形定位器在画面颈部偏右，绿色围巾不遮挡定位器；延续探险背包识别，在餐车动作中也不能随意消失。不要用整体镜像改变定位器位置，动作方向需要独立绘制或恰当的姿态设计。

本次文档不附已确认生产素材。进入美术制作前，向负责人取得可用角色参考并冻结；不能从低清旧界面截图抠图冒充独立高清角色。

| 资产组 | 首包应制作 | 质量要求 |
| --- | --- | --- |
| 场景 | 餐车、遮阳篷、柜台、前后景与固定热点 | 背景中不烘焙可移动物品和正式文字 |
| 主角 | 待机、取料、携带、递交、反应 | 同一比例/光源/纹理，动作不改变身份特征 |
| 客人 | 少量外形与到达/等待/接物/离场状态 | 外观与订单不固定绑定 |
| 食物 | apple、banana、bread、toast、空杯/果汁杯 | 独立透明资源，原料与成品差别可辨 |
| 设备 | 果汁机、烤面包机及工作状态 | 输入、过程、出口对应实际规则 |
| 操作资源 | 托盘、便签、食谱、音量/暂停等 | 同一风格，不拼贴通用 AI 图标 |

尺寸以最终显示大小与设备像素比倒推，透明道具必须核验 Alpha。每份资源记录 assetId、路径、实际宽高/字节/hash、Alpha、来源/制作工具、派生过程、用途、权利/审核状态。目标尺寸不是实际元数据，放大低清文件不能标为新高清原稿。

设计参考、原始生产稿和运行时导出分开。贴图表/合集不是全部独立资产。必须检查正式入口引用以及无遮挡效果；资源存在并不等于已接入。

## 8. 音频

英语请求与词句发音是前景通道，音乐和操作声让位。客人语音不得重叠；新的主动重听可以取消旧语音。设备音提示状态，但关闭声音仍看得懂机器何时完成。

按需预加载本场语音，播放必须记录是否真正开始、是否完成/中断及资源版本；这些不证明孩子听懂。首次手势激活声音，浏览器拒播提供重试/字幕支持路径。开发 TTS 明示未听审，不作为正式听力证据。

允许分别调低音乐与保留语音。进入后台暂停声音，回来由用户重听，不自动连续补播堆积请求。语音和例句由教研/听审确认，禁止无授权模仿真人声音。首版不录制儿童声音。

## 9. 体验否决条件

出现任一项，不继续扩关：主画面成为多张卡片和长表单；手机必须滚动才能拿料或交付；物品标签堆叠；点击正确选项自动配菜；场景只在提交后动一下；拿放、加工或递交缺少可见过程；英文和按钮小到依赖放大；通关截图靠预置状态生成。

负责人确认对象是运行中的场景与录屏，不是单张效果图。批准画面不代表英语/音频已审核，也不代表实体设备和儿童体验通过。
