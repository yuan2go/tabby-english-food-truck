# 狸花猫的英语餐车 / Tabby's English Food Truck

**听懂请求，动手准备，和狸花猫一起把每一份心意送到客人面前。**

独立仓库：`yuan2go/tabby-english-food-truck`。这是从零设计的单人、触控优先儿童英语网页游戏，不是英语学习网站或餐厅管理系统。

本轮 M1 直接拿取水果、操作果汁机、安排两个托盘并交付订单；烤面包机与完整场次留在后续设计。英语提供需求与协作信息；准备顺序、设备占用和有限台面形成游戏选择。默认没有惩罚倒计时，不要求每次拿食材先答题。

## 当前状态

M0 工程与 M1 双订单规则/可玩入口已建立：Phaser 场景、两位客人、两盘三槽、苹果汁加工、有限语法便签、恢复存档及本地开发语音。实际工程证据见 [STATUS](docs/STATUS.md)。

**M1 全量制作尚未完成**：仓库没有获准狸花猫参考，角色定稿及读便签/取料/携带/递交动作 BLOCKED。当前场景明确显示参考待确认，不是正式美术交付。其他图片为本轮独立生成候选，视觉与手感 AWAITING_OWNER_REVIEW；语音未听审。没有公开试玩部署，不进入 M2。

## 运行与检查

使用 Node >=22.12、npm，首次安装浏览器后从本目录运行：

```sh
npm ci
npx playwright install chromium
npm run dev
```

开发入口为终端显示的本地 HTTP 地址（默认 http://127.0.0.1:5173）。生产预览：`npm run build` 后 `npm run preview`。不通过双击 index.html 运行。

| 命令 | 实际用途 |
| --- | --- |
| `npm run typecheck` | 严格 TypeScript 检查 |
| `npm run lint` | Biome 格式与代码规则 |
| `npm run format` | 格式修整 |
| `npm test` | 纯规则、语言、快照与生命周期测试 |
| `npm run build` | 类型检查与 Vite 生产构建 |
| `npm run resources` | 校验真实资源尺寸/字节/hash/Alpha/引用 |
| `npm run test:browser` | 构建生产包，以 HTTP 启动 Chromium 操作测试，保留录像 |

资源重新导出：`node scripts/export-assets.mjs`；只有确实更新生产文件后才运行 `node scripts/manifest.mjs` 重登记，再执行资源检查。不要靠改清单掩盖坏资源。原稿、来源、权利与审核见 [art/README](art/README.md)。

## 怎么玩这两单

开摊后先看三页意义教学，再点客人听请求；需要时点“文字帮助”，支持会被保留记录。可以拖动食品，或先点食品再点目的地。按 Tab/Enter/Space 可操作相同对象，Esc 取消拿取。

- 苹果拖进机器上方入口，空杯放右侧杯座，点“开始榨汁”；5 秒有效游戏时间后取走杯中果汁。
- 苹果和香蕉直接装在同一盘，先选盘下方的盘把手，再点客人递出整盘。点盘里单个食品只编辑食品。
- 小猫便签可请求 `An apple`、`One apple`、`Two apples`、`An apple and a banana` 等；提交前明确选目标盘。它预留全部盘位，2 秒后落盘，也可撤回。当前取料食品轨迹可见，猫姿态制作仍受参考阻塞。
- 满盘可把食品换盘或点“放回”；果汁清理需确认。错误交付留住整盘，不自动交给另一位。
- 可以先交水果再交果汁，也可以等果汁后再准备水果；不检查固定解法，不限时处罚。完成后在餐车内短收尾并可重玩。

暂停、小食谱、失焦和后台冻结任务；便签编辑不暂停。刷新后首页提供继续。只使用 `tabby.foodtruck.save.v1` 和它的 previous 备份；损坏/未来版本保留原文并允许导出、确认重开，存储拒绝时本局临时运行。

## 独立重启边界

不 fork、不导入旧提交，不读取或复制旧项目的页面、组件、样式、关卡、状态模型、存档或工作包。产品目标与确认的狸花猫形象可以延续，但旧资产不得自动搬入；需要逐件确认用途、质量和来源。旧仓库保持原状。

首版以 Phaser 游戏场景为核心，TypeScript/Vite 构建，React 仅作薄外围与无障碍 DOM 层；具体依赖版本在新工程冒烟通过后锁定。不使用旧项目 lockfile，不把官方模板示例 UI 当产品设计。

## 第一交付目标

先完成正常首页可玩的双订单体验：苹果汁加工期间准备水果、在有限托盘中安排并交付，带真实小猫动作、语音、触控回退和保存恢复。负责人确认游戏观感和基本手感后，再扩展完整场次。不是先做课程导航、词语册和统计页面。

无账号、支付、广告、多人、后台或运行时 AI 依赖。代码授权与资产权利分别登记；本 README 不授予第三方素材使用权。
